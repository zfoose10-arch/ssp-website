# Build lane

A workflow skill: how this house runs a gated build session. Minted 2026-09-05 from the four sessions of that day (hooks, sandbox posture, data wall, the Judge), the learning crossing added the same evening, and pinned to the doctrine it mirrors: the Change Protocol v1.4, The Judge v2.5, Spec Contract v1.2, Rules Moved to Hooks v2.6, Build Lane v1.11, the three lines beside the halt class, the second lap and the handoff clause in the AIOP Build Doctrine v1.13, and the hard rules in 00 Identity/soul.md; each pin's dates live in the Authority Ledger's Build lane skill row. Reverify the pins at each bump; a mirror drifts silently.

## The delta prompt

A build prompt names five things and nothing else: the change; the upgrade or ruling behind it; this build's own constraints (surface, client scope, time box, what stops the session); the proof plan; the doctrine homes. Everything below is supplied.

## Phases, each with its exit condition

Every phase exit records the session's spend and progress on its build's item in the hub's queue: `~/scripts/build_queue.py record --item <id> --transcript <path> --met <durable lines met>` (07 Knowledge/Board.md, How a session records). Then `~/scripts/handoff_boundary.py budget --transcript <path>`; past the budget the session hands off at that exit (Budget, below). Three exits hand off regardless, B1 after the confirm, B2 after the scoped commits, B3 after the preflight: after the record and the budget read, `~/scripts/handoff_boundary.py boundary <confirm|build|judge> --transcript <path>` prints the order, the session writes that handoff file, and a fresh window resumes. The transcript is the session's own, as record takes.

1. **Gate.** Run `~/scripts/prebuild_gate.sh <surface>` first. Explain every bypass line it surfaces or say unexplained. Judge the dirty tree: the nightly's staging files and today's note accumulate by design and are left alone. Name the next scheduled leg. On GATE HOLD write `~/Downloads/gate-<surface>-<name>-<date>.md` and stop. When the session has the task tools, which the ruled build launch gives it (`CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude --model claude-opus-5-5 --effort high`, the builder pin, SSP_BUILDER_MODEL in ~/scripts/model_ladder.sh, at effort high by ruling 20), open one task per phase, in progress while in it and completed at its exit: a task left in progress at a stop draws the checklist nudge, a pending one does not. Then read this session's owner queue, `_system/queues/<slug>.md` for the owner the delta names or the surface implies by the README's keyword table (governance-repair for lane, gate, hook, ledger, skill, report, and proof work; judge; page-session; website; oracle; nightly), and start with its filed list: the proposal names which entries this build takes and which stay, and the report phase appends ` - taken <date>: <report name>` to each taken entry. Exit: GATE CLEAR recorded and the queue read.
2. **Recon and design.** Read what the delta names plus the doctrine this skill pins, and read current tool behavior by fetching the docs, never from memory, saving the excerpt and the version line to a dated file beside the proposal. Write `~/Downloads/<name>-proposal-<date>.md` in the Zane Brief shape and in the planning shape: the outcome, the constraints, three approaches with their trade-offs, one committed recommendation, and then the spec's first draft, and stop there; procedure is written only where a hard rule dictates a step. The spec is the build's contract, per 07 Knowledge/Spec Contract.md: durable lines, what must hold when the build is done, each falsifiable and each naming its proof, numbered D1 onward and marked apart from disposable lines, how we think we will get there; a baseline read from disk before any work starts; and a finish condition. The Judge verifies against the durable lines and never against the plan, so a durable line that cannot be proven is not written. Print a five line lead. Stop until Zane types confirm. Nothing is written outside Downloads before confirm. At confirm, B1: run `boundary confirm` and write the handoff, the confirm and its picks word for word under Chat rulings. Exit: confirm received and the handoff written.
3. **Build with proof.** Build. Every proof run appends one line to `~/scripts/_state/proof_runs.log` through the shared writer, `~/scripts/proof_line.zsh` or `~/scripts/proof_key.py write-line`, under its unit in `~/scripts/proof_units.conf`, never by hand: `<YYYY-MM-DD HH:MM:SS> <script> <closing count line or verdict> [key <16 hex> unit <unit> deps <n>]`, or `[key none unit <unit>: <reason>]`. A failing cell is fixed only under the scoped stop clause: the defect is in code this session or its same day predecessor shipped, the fix is proven again through the full matrix, `~/scripts/proof_key.py matrix` over every proof the report will cite, each unit rerun or trusted by its key, and the deviation is flagged in the report; a defect in standing machinery, a fix that cannot be reproven in full, or anything touching an authority stops the session. Inside that clause the fix walks the ladder: reproduce the failure before fixing it, and a defect that cannot be reproduced is investigated, not patched; no fix raises a limit or a retry count without a named cause; after a second failed fix on the same defect, the tried list is written to a file and handed to a fresh subagent with the instruction not to repeat it; after that, a rewrite plan with a reference implementation named, never a third patch; a third patch on the same defect halts to the Desk under For review. A mechanical check beats a model call wherever one can do the job. Exit: every cited proof green on its last run and logged.
4. **Doctrine homes.** Mint or amend what the delta names: the knowledge note, the doctrine rule, the hook or skill. Walk both build lane routers when the Build Doctrine moves. Then ask which context node would now mislead a future agent, the vault's root pointer, a folder rule, or a node beside a script, all listed in 07 Knowledge/Context Layer Map.md, and update it leaf first, stopping where the change no longer matters at the next level. Exit: every named home exists and cites the version, and no node the build made stale is left standing.
5. **Change Protocol.** Claim the ordinal through `~/scripts/ledger_ordinal.sh claim` before any ledger write. Add or amend rows; walk every dependent by reading and sync or flag it with today's date; retrue version cells in the same pass. Insert the history entry above the previous top entry, keeping that entry's marker in full, and predict the gate's top three ordinals before running it. Commit the ordinal after the entry. Exit: the gate's 4b and 4c agree and the entry names every row it touched.
6. **Scoped commits.** One commit per repo touched, by path, naming the ordinal, staging files untouched, attribution lines as the session requires. The report will name every file each commit changed, because the Judge matches by name. Then B2: run `boundary build` and write the handoff. Exit: every touched repo committed and the handoff written.
7. **Report, then the mechanical preflight.** Write `~/Downloads/<name>-session-<date>.md`: where he stands, one thing to know, next, as three short paragraphs; then a line; then Detail (what runs where), a Subagents section, `~/scripts/handoff_boundary.py subagents` over every window's transcript, a Spec section, Deviations flagged, Owed with an owner or trigger on every line, a BOUNDARY CONFIRMATION line naming every file written outside the vault and the hub, and the machine block as the report's last lines. The Subagents section ends with each window's Jev dollars from `~/scripts/spend_meter.py jev`. The Spec section is the heading Spec carrying every durable line of the proposal's spec, one per line as `- D<n> | <the line> | met, unmet, or not checkable | <what shows it>`, then a line beginning Baseline and a line beginning Finish; a met line names the proof that shows it, an unmet line is written as unmet and never argued past, and a not checkable line's last field reads `checkable by:` and the artifact that would have made it checkable. The Judge's eleventh check reads that section and an unmet line, a bare not checkable, or a missing section fails the report whatever the other eleven checks say. Every item the session holds appears; the wording compresses, never the list. The report describes the learning crossing as owed, never as done, because the crossing runs after the Judge's verdict and its queue entries and For review lines are its record; that Owed line names this session's phase 8 as its owner and the verdict file as its trigger. The machine block is where the Judge's mechanical checks read every fact, and never the prose: seven lines under a `MACHINE BLOCK` line, keys fixed, `ordinal:` the ordinal claimed or none; `commits:` every commit as `<repo> <hash> <path>, <path>`, semicolons between commits, repo names vault, scripts, hub, website, client, sidecar, paths as git show prints them; `scripts:` every proof script run, by path; `proof lines:` every proof log line this session wrote, verbatim with its key, semicolons between; `files:` every file written or changed, by path; `versions:` every doctrine version moved as `<doctrine> v<X.Y>`, or none; `verdict: pending, written by judge.sh` as the last line of the report. Then the preflight: run `~/scripts/judge_checks.py <report> <surface> ~/Downloads/judge-preflight-evidence-<name>-session-<date>.<YYYYMMDD-HHMMSS>.md`, answer any FAIL by correcting the block or the fact it reflects, and name the preflight and its evidence file in the report; the preflight logs its own proof line. When the report takes its closing day's name, run `~/scripts/build_queue.py report --item <id> --path <the report>` before the next record. Then B3: run `boundary judge` and write the handoff. Exit: the report stands alone, the preflight reads twelve of twelve, and the handoff written.
8. **Judge, then the learning crossing.** Before each lap run the full matrix through `~/scripts/proof_key.py matrix`. Run `~/scripts/judge.sh <report> <surface>`, which reruns the gate, runs the twelve checks into an evidence file, reads the report through two or three reviewer layers, the mechanical reader, the domain reader for the surface, and the client's champion where the report carries a CLIENT SCOPE line, each a fresh print run writing its observations, its spec walk, and its findings to `~/Downloads/judge-layer-<layer>-<report>.<stamp>.md`, and then runs the composer, which walks every durable line of the report's Spec section against the artifacts and the layers and writes the verdict with its Spec table; every file is kept under a run stamped name and the report's verdict line is pointed at the latest; take the verdict path from the report's last line. Lap one reruns every unit and reads cold; from lap two the Judge trusts a unit only by its unchanged key once a lap record holds a completed full pass, and its readers and composer read the delta under `~/Downloads/judge/<report name>/`; at every lap a cell listed in `_system/ruled_cells.conf` reads as ruled and named, never as a FAIL; a capped reader leg is rerun once on the narrower read, and a second cap fails the lap with the composer skipped. The Judge's target is the Spec section and the artifacts, never the proposal. A FAIL on a session that touched a governed authority or a client repo re enters the fix ladder and is re judged to PASS before the closing gate: the FAIL is answered by fixing what it found, never by rewording the line it found it on, and the report says what each lap fixed. This does not license rerunning a FAIL until it passes: each lap's findings are fixed, and the next lap judges the fix. Files moved between laps are named in the report's block, and every prior verdict is kept under its stamp. Where a PASS is unreachable because of a machine state Zane has ruled, the report says so and names the check. Then run `~/scripts/learning_crossing.py <report> --verdict <verdict>`, which extracts candidate lessons from the report's flagged deviations and the verdict's findings, writes each lesson that names an owner and a trigger to that owner's queue under `_system/queues/` (the same lesson raised twice collapsing into one entry), prints the rest under For the night, and logs the counts; read those, drop any whose fix already lives in a home, fold duplicates into one lesson, and write each open one as one plain register line under today's For review with a judged home, for the night's triage and Zane's ruling. The report's crossing record names the counts, queued, collapsed, and left for the night. Nothing is applied to a home by the session. Exit: the verdict file exists and the report's last line names it, the owned lessons are in their queues, and the unowned are under For review.
9. **Closing gate.** Run `~/scripts/build_queue.py done --item <id>`, which marks the build done and takes it off the Board, then `~/scripts/prebuild_gate.sh <surface>` as the last act. The terminal prints only the verdict line and the report path. Exit: GATE CLEAR.

## Standing constraints

- The five hooks are live: obey them, route around a refusal, never disable one.
- Three lines beside the halt class, from the AIOP Build Doctrine v1.13: a model's refusal of work outside the ruled bounds is a halt and never a rung on the ladder; a failed credential halts and is never worked around; an unattended run is scoped to the one to three hour reliability band, and anything longer is split at a checkpoint.
- The compaction handoff, ruled 2026-09-23: a build session that compacts does not continue on the summary. The compaction hook prints the order: write `~/Downloads/handoff-<name>-<date>.<stamp>.md` with the fields it names, commit nothing, claim nothing, and stop; rule H refuses every other write while the marker stands. The handoff never triggers a compaction. Since v1.10 the same marker, order and guard serve the boundaries, the budget and the spend line.
- Any output over 2,500 characters goes to a dated file under Downloads with a short terminal lead; the chat message is the pointer, not the deliverable.
- A CLIENT SCOPE line whenever a client repo is touched; that client's document home is never read unless the delta says so; every proof on fabricated fixtures.
- Nothing is deleted; duplicates merge into a survivor marked for Zane's hand. The one exception is soul.md's standing retention clause of 2026-09-23 for a Judge reviewer file under a client scope folder, read there and never restated here.
- Identity files are edited only under the token Zane writes by hand, after the proposed change is shown.
- No em dashes and no hyphen joining clauses, in any file and in every line a script prints.
- Working directory resets between shell calls: absolute paths always.
- One prompt at a time; a time box in the prompt is absolute: stop clean, commit nothing half done, and write the report saying where it stopped and what a resume prompt needs.

## Budget

Ruled by Zane 2026-10-02 from the session spend log's 9/30 and 10/01 rows; scripts read this line:

Budget: subagents 50 | subagent tokens 250000000 | spend line 150 dollars per window

A window is one transcript, so a resume starts at zero. Past either subagent ceiling the session hands off at its next phase exit; at the spend line, its transcript and subagents priced, the stop hook logs the crossing row and refuses the stop once.

## Resume

A stopped session, by a time box, a hold, or a handoff, names the phase it stopped in and the artifacts that exist, in its report or its handoff file. The resume prompt names that file and says continue, and the session runs the resume phase:

1. **Gate.** Run `~/scripts/prebuild_gate.sh <surface>` as phase 1 does.
2. **Check.** On a handoff, run `~/scripts/handoff_check.py <handoff>`; a finding is reconciled from disk before anything else, never from the summary the handoff was written on. After a boundary its RESUME line names the phase to continue at.
3. **Read.** The proposal the handoff names and the handoff, whole, and any chat ruling it carries is written into the day's note in the close grammar.
4. **Carry.** Claim no second ordinal when one is claimed and uncommitted for the build: the handoff's Claimed ordinal line is what the stop hook counts as this session's claim. An identity edit the handoff names is shown to Zane again and waits for a token written after this session started.
5. **Continue** at the named next step. A Judge lap the handoff names in flight has an unproven fix: reproduce the finding, finish the fix under the scoped stop clause, rerun the full matrix through `~/scripts/proof_key.py matrix`, then run the next lap, every prior verdict kept.

Exit: the next step taken, the gate clear and the ordinal carried.

Once Zane arms it, `~/scripts/resume_wrapper.sh` launches a boundary handoff that needs nothing from him, once and outside the proof window; a handoff written for it carries nothing outside its eleven fields, and any other leaves one Desk line (Build Lane, What a resume looks like).
